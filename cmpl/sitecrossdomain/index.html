Test Case: CT-1011 — Cross-Domain Consent Validation

Domain key: sitecrossdomain (primary property)

Purpose: Simulates a group of properties that share one consent record. The test checks that a shared consent scope is actually disclosed to the visitor — on the banner and in the preference center — and that the preference center names and links every property the shared record covers, instead of referring to them generically as "our family of sites".

Welcome to SiteCrossDomain

This property is the primary member of a consent group. A consent decision taken here is meant to apply to the sibling properties below as well, which is precisely the scope that has to be disclosed before the decision is taken.

Shop property →Second member of the same consent group Blog property →Third member of the same consent group
[PLACEHOLDER] Cookie consent banner renders here once the CMP SDK snippet is added to the page head.

Setup required before scanning

  1. Register all three property URLs in the consent admin portal as separate domains.
  2. Create one cross-domain consent group and add all three domains to it.
  3. Turn on the group's additional banner text so the banner itself states that the choice applies across the group.
  4. Turn on show covered domains in the preference center so the preference center enumerates and links each member.
  5. Give the group a title and description that spell out the shared scope.
  6. Paste each property's SDK snippet into its own page head, then scan.

What the scanner expects to find here

  • CMP config exposes a cross-domain consent block, enabled, listing the peer properties
  • Banner body text discloses that consent reaches beyond this property
  • Preference center opens, and its text discloses the same shared scope
  • Preference center names and links every covered property, not a generic phrase
  • Expected result: pass

Variants this site can produce

  • Fail — banner silent: turn the additional banner text off, leave the preference center disclosure on.
  • Fail — preference center silent: clear the group title and description.
  • Fail — domains not enumerated: leave the disclosure wording on but turn off showing the covered domains in the preference center, so no member is named or linked.
  • Not applicable: disable the cross-domain consent group. Consent is then scoped to this property alone and there is no shared scope to disclose.
  • Partially performed: scan a property whose CMP does not publish a cross-domain consent block at all. Absence of a sharing relationship cannot be confirmed, so the test degrades rather than passing as not applicable.
Single-host caveat. All three properties are served from the same host here, so this setup exercises the full disclosure and enumeration logic but not a genuine cookie handoff between two different registrable domains. For that, host one member on a separate domain and add it to the same group.
